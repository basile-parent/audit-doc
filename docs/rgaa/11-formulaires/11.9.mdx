# Dans chaque [formulaire](https://accessibilite.numerique.gouv.fr/methode/glossaire/#formulaire), l’intitulé de chaque [bouton](https://accessibilite.numerique.gouv.fr/methode/glossaire/#bouton-formulaire) est-il pertinent (hors cas particuliers) ?

<CriteriaA/>
<IconedLink>[Lien RGAA](https://accessibilite.numerique.gouv.fr/methode/criteres-et-tests/#11.9)</IconedLink>
<BookmarkletTags names={["11.1 Formulaires"]} />

## Que vérifie-t-on ?

Lorsque le nom visible et le nom accessible sont deux implémentations différentes,
il faut veiller à ce que **le nom visible soit repris au moins dans le nom accessible**.

<details>
    <summary>
        ## Exemples
    </summary>

    <Example comply>
        ```html
        <input type="submit" value="OK" title="Envoyer mon message" />
        ```
        Le nom visible est construit à partir de l’attribut `value` qui constitue également le nom accessible : « OK ».
        L’attribut `title` dans ce cas est la description accessible, et permet de rendre l’intitulé « OK » pertinent.
    </Example>
    <Example>
        ```html
        <input type="submit" value="OK" aria-label="Envoyer mon message" />
        ```
        Le nom visible est construit à partir de l’attribut `value` (« OK ») et le nom accessible est construit
        à partir de la propriété `aria-label` : « Envoyer votre message ». Le nom visible n’est pas contenu
        dans le nom accessible.
    </Example>
    <Example comply>
        ```html
        <button aria-label="Ok envoyer mon message">OK</button>
        ```
        Le nom visible est construit à partir du nœud texte « OK ») et le nom accessible est construit à partir
        de la propriété `aria-label` : « Ok envoyer mon message ». Le nom visible est contenu dans le nom accessible.
    </Example>
    <Example imgImport={CGoogle} comply>
        Sur la page de recherche [google.com](https://www.google.com/search?q=accessibilit%C3%A9&client=firefox-b-d&sxsrf=APq-WBtQoA3bV1JPnNRT4l5-V5y5WXuudA%3A1649738931975&ei=swRVYvGJO6KSlwSMkYLwDw&ved=0ahUKEwixr4y43I33AhUiyYUKHYyIAP4Q4dUDCA0&uact=5&oq=accessibilit%C3%A9&gs_lcp=Cgdnd3Mtd2l6EAMyBAgjECcyBAgjECcyCAgAEIAEELEDMgUIABCABDIFCAAQgAQyBQgAEIAEMgUIABCABDIFCAAQgAQyBQgAEIAEMgUIABCABDoHCCMQsAMQJzoHCAAQRxCwAzoKCAAQsQMQgwEQQzoECAAQQ0oECEEYAEoECEYYAFDLBFjICmDmC2gBcAF4AIABYYgBoQKSAQEzmAEAoAEByAEKwAEB&sclient=gws-wiz),
        le bouton de soumission du formulaire de recherche n’a pas de nom visible (contrairement aux champs de
        formulaires, il n’est pas obligatoire d’avoir un intitulé de bouton visible). Le nom accessible est créé
        à partir de la propriété `aria-label` : « Rechercher ».
    </Example>
    <Example imgImport={NCGoogle}>
        Sur la page de [recherche de vols de Google](https://www.google.com/travel/flights?gl=FR&hl=fr),
        le bouton d’envoi a un nom visible « Explorer » qui n’est pas repris dans le nom accessible « Rechercher
        des destinations » (donné par `aria-label`).
    </Example>
</details>

:::warning

On vérifie bien ici les boutons **de formulaire**. L'intitulé des boutons présents dans la page dans un autre contexte
(ouverture de popup, chargement de données, etc.) sera évalué sur le [critère 7.1](../scripts/7.1).

:::

## Aide à la détection
<BookmarkletTags names={["11.1 Formulaires"]} />

- Le bookmarklet donne le nom accessible calculé, vérifier que chaque bouton de formulaire a un nom accessible défini
- Vérifier ensuite les noms accessibles des champs au regard des différents tests du RGAA
    - Le nom accessible est pertinent (l’utilisateur comprend l’action du bouton)
    - S’ils sont différents, le nom visible est repris dans le nom accessible
