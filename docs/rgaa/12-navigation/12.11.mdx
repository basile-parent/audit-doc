# Dans chaque page web, les contenus additionnels apparaissant au survol, à la prise de focus ou à l’activation d’un [composant d’interface](https://accessibilite.numerique.gouv.fr/methode/glossaire/#composant-d-interface) sont-ils si nécessaire atteignables au clavier ?

<CriteriaA/>
<IconedLink>[Lien RGAA](https://accessibilite.numerique.gouv.fr/methode/criteres-et-tests/#12.11)</IconedLink>

## Que vérifie-t-on ?

Lorsqu'un contenu est ajouté, il doit être parcourable de manière logique. Exemple :
- Si c'est un tooltip avec un élément intéractif : la prochaine tabulation doit positionner le focus sur cet élément
- Si du contenu a été ajouté, le focus est positionné sur le premier élément ajouté

Erreurs typiques :

- l’absence de repositionnement de focus logique après une action de l’utilisateur dans la page
- menu déroulant : lorsqu’un sous-menu est affiché à la prise de focus, le parcours de la tabulation doit continuer
dans le contenu affiché
- les rechargements de page dans les SPA (type React) qui ne provoquent jamais de repositionnement
de focus en haut de page
- contenu additionnel : lorsqu’un contenu additionnel est affiché (à la prise de focus, au survol ou à
l’activation d’un composant) et qu’il contient un élément interactif (lien, bouton), il doit pouvoir être
atteint au clavier

## Notes techniques

Ce critère adresse les situations où un contenu additionnel contient des
[composants d’interface](https://accessibilite.numerique.gouv.fr/methode/glossaire/#composant-d-interface)
avec lesquels il doit être possible d’interagir au clavier. Par exemple, une infobulle personnalisée qui propose
un lien dans son contenu.
