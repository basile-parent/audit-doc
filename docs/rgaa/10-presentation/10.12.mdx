# Dans chaque page web, les propriétés d’espacement du texte peuvent-elles être redéfinies par l’utilisateur sans perte de contenu ou de fonctionnalité (hors cas particuliers) ? [](https://accessibilite.numerique.gouv.fr/methode/criteres-et-tests/#10.12 "Lien vers le critère 10.12")

<CriteriaAA/>
<IconedLink>[Lien RGAA](https://accessibilite.numerique.gouv.fr/methode/criteres-et-tests/#10.12)</IconedLink>
<BookmarkletTags names={["10.12 Espacement"]} />

## Que vérifie-t-on ?

Les textes doivent rester lisibles dans les conditions suivantes :
- espacement entre les lignes augmenté de 1,5 fois la taille de police
- marge entre paragraphes (`margin-bottom`) augmentée de 2 fois la taille de police
- espacement des lettres (`letter-spacing`) augmenté jusqu’à 0,12 fois la taille de la police
- espacement des mots (`word-spacing`) augmenté jusqu’à 0,16 fois la taille de la police

Note : une implémentation de ces règles de modification est disponible dans les ressources du critère de succès
WCAG 1.4.12 : [text-adaptation.js](https://github.com/alastc/adaptation-scripts/blob/master/scripts/text-adaptation.js)

## Aide à la détection
<BookmarkletTags names={["10.12 Espacement"]} />

- Tester la page dans une **fenêtre de 1280px** avec les CSS activées.
- Vérifier que tous les textes restent lisibles.

Penser aux contenus à **l’intérieur des menus, fenêtres modales, accordéons, carrousels...**

## Cas particuliers

Font exception à ce critère, les contenus pour lesquels l’utilisateur n’a pas de possibilité de personnalisation :

*   Les sous-titres directement intégrés à une vidéo ;
*   Les images texte ;
*   Le texte au sein d’une balise `<canvas>`.
