# Pour chaque page web, les [contenus cachés](https://accessibilite.numerique.gouv.fr/methode/glossaire/#contenu-cache) ont-ils vocation à être ignorés par les technologies d’assistance ?

<CriteriaA/>
<IconedLink>[Lien RGAA](https://accessibilite.numerique.gouv.fr/methode/criteres-et-tests/#10.8)</IconedLink>
<BookmarkletTags names={["10.8 Contenus cachés"]} />

## Rappels

Les contenus cachés n’ont pas vocation à être disponibles pour les technologies d’assistance.

Contenu caché en CSS :
- `display:none` (cas typique des cases à cocher ou boutons radio)
- `visibility:hidden`
- `font-size:0`

Contenu caché en HTML :
- `aria-hidden="true"`
- `hidden`

<details>
    <summary>
        ## Exemples
    </summary>

    <Example imgImport={NCBooking}>
        Sur la page d’accueil de [booking.com](https://www.booking.com/), les boutons permettant la navigation dans
        certains carrousels sont intégrés dans des conteneurs masqués avec `aria-hidden="true"`. Les utilisateurs
        aveugles et de commande vocale ne pourront jamais activer ces composants.
    </Example>

    <Example imgImport={NCActive}>
        Sur le site [auto.activeassurances.fr](https://auto.activeassurances.fr/auto-active-assurance/rollover/page0?QA1_Projet=1),
        dans le formulaire de simulation, les boutons radio sont cachés en CSS (`display:none`) pour créer un effet
        de style. L’étiquette est cliquable et activable au clavier, mais n’a pas un rôle pertinent.

        Pour corriger, on pourra recommander la suppression de l’attribut `tabindex="0"` sur les éléments `<label>`
        et de la propriété CSS `display:none` sur les cases à cocher et boutons radio à positionner hors écran. Il
        n’est pas possible de simplement ajouter un rôle ARIA sur la balise `<label>` (usage interdit de la
            propriété `role` sur cet élément).
    </Example>
</details>

## Aide à la détection : contenus cachés
<BookmarkletTags names={["10.8 Contenus cachés"]} />

Repérer les contenus masqués avec `hidden` et `aria-hidden="true"` et vérifier s’ils doivent être rendus accessibles ou non.

Note : le bookmarklet ne met pas en évidence les éléments masqués avec CSS.

## Notes techniques

WAI-ARIA propose un attribut `aria-hidden` (`true` ou `false`) qui permet d’inhiber la restitution d’un contenu 
en direction des technologies d’assistance, sans action sur sa visibilité en direction des agents utilisateurs : 
un contenu avec `aria-hidden="true"` ne sera donc plus vocalisable, mais restera visible.

Sauf si le contenu contrôlé par `aria-hidden` n’a pas vocation à être restitué par les technologies d’assistance, 
la valeur de l’attribut `aria-hidden` doit être cohérente avec l’état affiché ou masqué du contenu à l’écran.

La spécification HTML5 propose un attribut `hidden` qui permet de rendre indisponible (quand l’attribut `hidden` 
est présent) un contenu dans le DOM généré (de manière similaire au `type="hidden"` sur un contrôle de formulaire).

Il est possible d’avoir des situations où un contenu contrôlé par `hidden` ou `aria-hidden` se trouve momentanément 
dans un état incohérent avec le statut affiché ou masqué du contenu, par exemple si l’on désire rendre disponible 
un élément, mais que son affichage à l’écran reste dépendant d’une action ultérieure. Dans ce cas, c’est l’état final 
du contenu qui doit être considéré.
